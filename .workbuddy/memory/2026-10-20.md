# 2026-10-20

## ArduPilot Cygwin64 编译环境修复

用户环境：Windows + Cygwin64 原生 `./waf copter`（目标板 MicoAir743v2 / STM32H743）。

根因：不是代码问题，是 Cygwin 的 Python 3.12 缺少构建所需模块（Cygwin 的 python3 包不自带 pip，ensurepip 的 bundled wheel 也被裁掉了）。逐个补齐：
- `pip 26.2.1`：用 `get-pip.py --user` 引导安装（`engineer` 需注意 cygwin 下 curl 写 /cygdrive 会 curl error 23，改用 Windows 侧 Python urllib 下载再交给 cygwin python 执行）
- `empy==3.3.4`（必须 3.3.4，em.py 模块；4.x 不兼容）→ 报错来源 `Tools/AP_Periph/wscript:10`
- `pexpect` + `pyserial`（`Tools/ardupilotwaf/chibios.py` 上传/串口任务）
- `future`（`modules/mavlink/pymavlink/generator/mavgen_c.py` 依赖 `future.utils.iteritems`）

结果：`'copter' finished successfully (2m37s)`，产物 `build/MicoAir743v2/bin/arducopter.apj`（1.3M）、`arducopter.bin`（1.5M），Flash 用量 1475004/1703936 B。

已知无害噪声：configure 阶段 `endian.h` / `byteswap.h` / `memrchr` 检查打印 "Test does not build" + "The configuration failed"，属目标端（ARM newlib）非必需头文件检查，`mandatory=False`，不影响构建。

### 坑：`pip --user` 装错位置导致"装了还是报错"

第一次用 `--user` 安装，因为调用时继承了 Git Bash 的 `HOME=C:\Users\CICORE`，包装到了 `C:\Users\CICORE\.local\lib\python3.12\site-packages`；而用户自己打开的 Cygwin 终端 `HOME=/home/CICORE`，`sys.path` 里根本没有那个目录 → 仍然报 `you need to install empy`。

正确做法（已采用）：装到 **Cygwin 系统 site-packages**，与 HOME 无关：
`C:\cygwin64\lib\python3.12\site-packages`（Cygwin 里 `/usr` 映射到 `C:\cygwin64`，即 `/usr/lib/python3.12/site-packages`）。
本次是直接 `cp -r` 从用户 site 复制 em.py / empy-3.3.4.dist-info / pexpect / ptyprocess / serial / pyserial-3.5 / future / past / pip，纯 Python 无需编译。

验证方式：`env -u HOME /c/cygwin64/bin/bash.exe -lc '...'` 让 bash 自己从 passwd 取 HOME=/home/CICORE，再确认模块从 `/usr/lib/python3.12/site-packages` 加载。

最终：`./waf clean` + 完整重建 1012 步通过，`'copter' finished successfully (2m35s)`。

注：`mv build build_prev` 会 Permission denied（有句柄占用），需要从零验证时用 `./waf clean` 而不是删目录。
