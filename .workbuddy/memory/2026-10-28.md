## 光流定点 EKF 原点设置脚本

用户需求：光流定点时地面站（Mission Planner）无法手动设置 EKF 原点。

### 背景分析
- ArduPilot 中 `home` 与 `EKF origin` 是独立概念。`MAV_CMD_DO_SET_HOME` 只设 home，不碰 EKF origin。
- 已有入口 `SET_GPS_GLOBAL_ORIGIN` → `GCS_MAVLINK::set_ekf_origin()`（GCS_Common.cpp:3764），但 `set_ekf_origin` 内部 `if (ahrs.get_origin()) return;` 会拒绝覆盖已设原点。
- `AP_AHRS::set_origin()`（AP_AHRS.cpp:1456）是真正的写入点，脚本引擎已绑定为 `ahrs:set_origin(location)`。

### 产出
新建脚本 `libraries/AP_Scripting/examples/copter-set-ekf-origin.lua`：
- 参数表 key=73，前缀 `EKFO_`，6 个参数（MODE/LAT/LNG/ALT/FORCE/TRIG），带 @Param 元数据。
- 坐标来源：EKFO_MODE=0 用当前 GPS 3D fix；=1 用预设 EKFO_LAT/LNG/ALT。
- EKFO_FORCE=1 可强制覆盖已设原点（绕过 set_ekf_origin 的限制）。
- 触发：方式 A 用 RCx_OPTION=300 拨高位；方式 B 把 EKFO_TRIG 从 0 改 1（脚本自动复位）。

### 关键 API 确认（来自 bindings.desc + 官方示例）
- `Parameter:get()` 直接返回数值；`Parameter:set(v)` 返回 bool。
- `gps:status(0)` 单参数、`gps.GPS_OK_FIX_3D` 枚举访问、`gps:location(0)` 均正确。
- `Location` 的 lat/lng/alt 是 field，生成 `:lat()` getter 和 `:lat(v)` setter（示例 ahrs-set-origin.lua 验证）。
- `param:add_table`/`add_param` 幂等，官方 applet 用 assert 包裹是标准模式。
